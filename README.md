Motivo das escolhas dos padrões.

Questão 1 - Chain of Responsability - Após ler o enunciado, percebi que ele menciona a utilização de diferentes algoritmos para o cálculo das métricas de risco. Diante disso, concluí que o padrão Chain of Responsibility seria o mais apropriado, pois, ao final do enunciado, também é citado que o sistema deve “mudar dinamicamente durante a execução”. Essa característica se alinha perfeitamente à ideia do padrão, que permite alternar entre diferentes responsabilidades em tempo de execução.

Questão 2 - Adapter - Após ler o enunciado, percebi que ele descreve um sistema legado complexo, no qual alguns componentes encontram-se incompatíveis. Diante disso, considerei que o padrão Adapter seria a escolha mais adequada, pois ele permite criar um GatewayAdapter capaz de tornar os métodos antigos compatíveis sem a necessidade de alterar o código-fonte original.

Questão 3 - State - Após analisar o enunciado, notei que o sistema de controle da usina nuclear apresenta diferentes estados de operação — DESLIGADA, OPERAÇÃO_NORMAL, ALERTA_AMARELO, ALERTA_VERMELHO e EMERGÊNCIA —, cada um com comportamentos específicos. Diante dessa característica, o padrão State se mostra a escolha mais adequada, pois permite que o objeto altere dinamicamente seu comportamento conforme o estado atual, sem necessidade de estruturas condicionais extensas. Dessa forma, o sistema se torna mais organizado, flexível e fácil de manter.

Questão 4 - Chain of Responsability - Ao analisar o enunciado, observei que o sistema de validação de documentos fiscais eletrônicos (NF-e) precisa aplicar múltiplas regras de validação em sequência. Diante disso, o padrão Chain of Responsibility é o mais adequado, pois permite encadear diferentes validadores, onde cada um executa sua verificação e, se necessário, passa o processamento adiante. Esse padrão torna o sistema mais modular, flexível e fácil de manter, além de permitir adicionar ou remover novas regras de validação sem alterar a estrutura principal do código.
